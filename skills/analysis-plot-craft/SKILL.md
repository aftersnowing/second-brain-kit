# 분석 도면 제작

15척 함대 검증에서 도면 20여 종 × 15개체를 만들고, 사용자 지적으로 여러 번 갈아엎으며 배운 것.

## 요지

도면은 분석의 부산물이 아니라 **결론이 전달되는 경로**다. 실패는 세 축에서 난다.

1. **안 읽힘** — 레이아웃·폰트·색. 내용이 맞아도 전달이 안 된다.
2. **안 맞음** — 비교 기준이 잘못되어 그림이 다른 결론을 말한다. **가장 비싼 실패.**
3. **안 통함** — 용어·톤이 독자(분석가가 아님)와 안 맞는다.

그리고 검증 기준은 언제나 **렌더된 결과**다. 코드나 글자수로 판단하면 틀린다.

## 착수 전에 정할 다섯 가지

| 결정 | 잘못 잡으면 |
|---|---|
| 독자 | 톤·용어 전체를 다시 써야 함 |
| 스토리라인 상 위치 | 중복 도면이 쌓임 (원자료→필터→정규화→보정→산점→적합 중 어디인가) |
| 산출 단위 | 개체별만 만들면 전체 조망이 없고, 전체만 만들면 근거 추적이 끊김 — **둘 다 설계** |
| 축 | 아래 참조 |
| 비교 기준 | 결론이 뒤집히거나 눈속임이 됨 |

## 비교 기준이 결론을 만든다

- **기준을 무엇으로 잡느냐가 메시지를 바꾼다.** 개체별 계약 기준선 대비로 그렸더니
  "기준이 후한 개체가 좋아 보이는" 그림이 됐다. 사용자 지적으로 **동급 평균 대비**로 바꾸자
  귀속이 정직해졌다. 기준선이 개체마다 다르면 그 축으로 서열을 그리지 마라.
- **오해 소지가 있는 비교는 아예 빼라.** 서로 다른 계약표를 쓰는 개체들을 한 패널에서 계약 대비로
  비교하는 것은 정보가 아니라 잡음이다(해당 패널에서 그 계열을 제거했다).
- **지표들은 같은 운전점에서 읽어 정합시킨다.** 세 패널이 각각 다른 조건에서 계산되면 곱셈이
  안 맞는다. 동일 운전점으로 통일하자 `Power +6.3% ⊗ SFC +7.1% = DFOC +13.7%`로 맞아떨어졌고,
  그 자체가 그림의 설득력이 됐다.
- **축은 데이터 현실에 맞게 고른다.** 속도 채널이 불량한 개체는 속도축 대신 부하(%MCR)축으로
  그리는 편이 정직하다. 축을 고정해두고 나쁜 데이터를 억지로 얹지 마라.

## 텍스트 최소화

- **그래프와 숫자가 설명하게 한다.** 헤더는 제목 1줄 + 기준 1줄(단위·보정 여부·제외 구간)까지.
  방법론 산문은 문서로 뺀다.
- **수치 결론은 산문이 아니라 패널 내 칩**으로. 헤더에서 되풀이하면 그대로 중복이다.
- **하단 각주 블록(fig.text, y<0.12)은 기본 금지.** 전폭으로 흘러 레이아웃을 밀어낸다.
  실제로 부제 2줄 + 강조 1줄 + 각주 2줄이 쌓여 도면이 깨졌는데, 그 수치는 이미 패널 안 칩에
  있어 전부 중복이었다.
- **예외 — 계열명 용어집**: 이름만으로 구분되지 않는 계열(metered / measured / yard book 등)은
  여백에 작게 정의를 다는 게 낫다. 금지의 이유가 *레이아웃 파괴*였으므로 **여백을 먼저 확보하면
  금지 대상이 아니다.**
  - `tight_layout(rect=...)`이 아니라 **`subplots_adjust(bottom=…)`로 밴드를 확보**한 뒤
    figure 좌표로 배치. (tight_layout이 rect를 무시하고 "not compatible" 경고를 내며 글자가
    축 위로 겹친 사례가 있다.)
  - **`savefig(bbox_inches="tight")`는 확보한 여백을 다시 잘라내므로 제거.** 단 제거하면
    캔버스가 넓어져 우측 값 라벨이 잘릴 수 있으니 x 여유를 별도로 확보한다.
  - 형식은 **용어(볼드, 우측정렬) + 정의(회색, 소폰트)** 2단.
- **범례 라벨은 짧게**, 괄호 설명 금지.
- 판정은 **글자수가 아니라 렌더된 도면**에서. 글자수 기준은 과잉 검출된다(정상 도면도 200자대가 흔함).
- 이 규범은 **납품 경로 도면에만** 적용한다. 일회성 탐색 스크립트까지 강제하지 말 것.

## 색·강조 규약

- **무채색 + 단일 강조색**이 기본. 컬러 남발은 임원 문서에서 신뢰를 깎는다.
- **색이 의미를 갖게 하고 전 도면에서 고정**한다. 예: 계약/기준선 = 빨강, 제조사 그룹별 밴드색,
  주목 개체만 강조하고 나머지는 회색. 강조 대상을 인자로 받아 `-`이면 무강조로 두면 같은
  스크립트로 15장을 만들 수 있다.
- **연속 변수는 컬러바**로 표현한다(등급·강도 등). 계열 5개가 넘어가면 색 구분이 실패하므로
  범례 대신 컬러바나 패널 분할을 쓴다.
- 규약은 `analysis-asset-kit`에서 받는다 — `ACCENT`(단일 강조) · `SERIES`(무채색 4단) ·
  `STATUS`(판정 칩 전용). **도면마다 색을 새로 고르지 않는다.** 한 저장소에 스타일 모듈이
  4개까지 늘어난 적이 있고, 그중 하나는 자기가 유일한 정본이라고 적혀 있었다.

## ★ 폰트: 리포트에 축소 삽입된다는 걸 잊지 마라

가장 자주 놓치는 함정이다. 도면은 보통 리포트에 **0.72~0.95배로 축소 삽입**되므로,
네이티브에서 읽히던 9pt가 인쇄본에서는 6.5pt가 된다.

**직접 계산하지 말고 `analysis-asset-kit`에서 받는다.** 하한은 상수가 아니라 삽입 배율의
함수이고, 상수로 박는 순간 다른 용도의 도면에서 틀린다.

```python
from analysis_kit import tiers, configure, style_axis
t = tiers(embed_scale=0.72)   # 리포트 본문 삽입 → floor 12.5pt
t = tiers(embed_scale=1.0)    # 도면이 곧 페이지 → floor 9.0pt
configure(t); style_axis(ax, t)
```

- `embed_scale`은 **가장 작게 들어갈 배율**을 넣는다. 도면은 최악의 배치만큼만 읽힌다.
- 어떤 티어도 `floor` 아래로 지정될 수 없다(키트가 테스트로 고정).
- **폰트 하한 검사를 빌드 게이트로 전진배치**한다(아래 린터의 `font_below_floor`).
- 모듈마다 폰트 티어가 다르면 통일 전에 "시각적 회귀 없음"을 확인해야 한다 — 애초에 한 곳에서
  받는 이유다. 실제로 한 저장소의 두 스타일 모듈이 하한 10pt와 12.5pt로 갈렸는데, **둘 다
  옳았다.** 하나는 도면이 페이지였고 하나는 0.72배 삽입이었다. 상수로 박았기 때문에 서로 틀렸다.

## 한글·글꼴

- 한글 라벨은 폰트가 없으면 □(tofu)로 깨진다. **`configure(t)`가 이미 처리한다** — CJK 가용
  폰트를 우선순위로 탐색하고 `axes.unicode_minus=False`(음수 부호 깨짐)까지 잡는다.
  직접 `rcParams`를 건드리지 말 것. tofu는 린터가 못 잡고 독자만 본다.
- **★ `$` 는 수식 모드를 연다 — 린터가 원리적으로 못 잡는 토푸.** matplotlib 텍스트에서
  `$`가 짝을 이루면 그 사이가 mathtext로 조판되고, 수식 폰트에 CJK 글리프가 없어 □로
  인쇄된다. **bbox는 정상이라 `audit_figure` 7종을 전부 통과하고**, `configure(t)`의 CJK
  폰트 탐색도 이 경로는 막지 못한다. 통화는 `USD`로 적어 `$`를 아예 쓰지 않는 것이 안전하다.
  게이트를 둔다면 렌더된 결과가 아니라 **소스**를 본다 — matplotlib을 실제 import하는
  모듈의 이스케이프 안 된 `$` + 렌더된 PDF 텍스트의 `$`.
- **납품 도면은 영문 라벨을 권장**하고, 한글 서술은 본문·README·subtitle 텍스트로 뺀다.
  폰트 가용성이 수령자 환경마다 다르기 때문이다.

## 곡선·적합·외삽 표현

- **검증된 fitter를 재사용**하고 자작 곡선(임의 power-law, binned median)을 그리지 않는다.
  결과가 비일관해지고 같은 데이터에서 도면마다 다른 곡선이 나온다.
- **외삽은 점선 + 지지 범위 경계 표시.** 관측이 뒷받침하는 구간과 아닌 구간이 한눈에 갈려야
  한다. 표에서는 †로 표기하고, 도면에서는 선 스타일로 구분한다.
- **산점 소스를 하나의 캐시로 통일**한다. 도면마다 다른 소스에서 점을 뽑으면 같은 그림이
  미묘하게 달라지고, 나중에 어느 것이 맞는지 아무도 모른다.
- 적합 결과를 보여줄 때는 **점(bin 중앙값) + 실선(적합) + 회색 점선(기준 곡선)** 3계열이
  기본형. 원시 점을 2D 밀도로 뭉개면 개체 비교가 불가능해진다(실제로 production 도면이
  이 문제로 재작성됐다).

## 재사용과 템플릿

- **새 도면을 만들기 전에 기존 산출물의 실제 이미지를 눈으로 확인**하고 그 생성 스크립트를
  재현하라. 형식도 재사용 대상이다. 자작 3-panel scatter는 수준 이하로 취급된다.
- **개체별/전체 도면은 렌더 헬퍼를 공유**한다(`render_<thing>_row()` 식). 한 코드로 두 단위를
  만들면 규약이 자동으로 일치한다.
- 도면이 20종을 넘어가면 **대장(신설/이동/폐기)을 관리**한다. 안 그러면 중복 도면이 쌓이고
  어느 것이 본문용인지 모르게 된다.

## 기계 검증 — 도면 QA 린터

**`analysis-asset-kit`의 린터를 쓴다. 새로 만들지 않는다.**

```python
from analysis_kit import audit_figure
findings = audit_figure(fig, min_font_pt=t.floor, furniture_rules=(0.047, 0.955))
```

`min_font_pt`에 기본값이 없는 것은 의도다 — 모듈 상수로 두면 리포트 본문용 도면이 조용히
통과한다. 결과는 반환되고 raise되지 않는다(빌드를 중단시키는 린터는 꺼진다).
아래 일곱 가지만 잡아도 대부분 걸린다.

| 검사 | 잡는 것 |
|---|---|
| `empty_axes` | 아무것도 안 그려진 차트 — **가장 조용한 실패** |
| `text_overlap` | 캡션·제목이 차트나 표 위에 얹힘 |
| `text_off_page` | 텍스트가 페이지 밖으로 |
| `text_on_furniture` | 텍스트가 페이지 괘선(머리글·꼬리말 선)을 가로지름 |
| `text_collision` | **글자끼리 겹침** — 짧은 문자열 둘이 겹치면 멀리서 한 줄로 보여 검토를 통과함 |
| `cell_clipped` | 표 텍스트가 셀보다 넓어 잘림 |
| `font_below_floor` | 인쇄 하한 미만 폰트 |

- 구현은 렌더러에서 각 artist의 bbox를 얻어 겹침 비율·경계 초과를 계산하면 된다.
- **첫 전수 스윕이 아무도 열어보지 않은 페이지에서 실결함 2건을 잡았다**(전 15개체의 부록
  텍스트가 표를 100% 침범). 사람이 매번 열어보는 방식으로는 절대 못 찾았을 것이다.
- **stale 게이트도 함께**: 도면이 옛 값으로 그려지지 않도록, 입력이 정본과 불일치하면
  생성을 차단한다(허용 오차 1e-9 수준으로 잡았다).

## 프리뷰 루프 — 도면 하나 보려고 전체를 빌드하지 마라

- 패키지 전체 빌드가 80초 걸리고 수백 파일을 쓰는데, 도면 한 장 확인하려고 그걸 돌리는 게
  가장 흔한 낭비다. **캐시에서 지정 페이지만 렌더하는 프리뷰 도구**를 만들어라(수 초).
- 옵션 세 가지면 충분하다: `--page <이름>`(한 장), `--page all --contact-sheet`(전 페이지 타일),
  `--audit`(이미지 없이 린터 결과만).
- **프리뷰가 현재 코드로 못 만드는 그림을 보여주면 안 된다.** 입력·분석 코드가 캐시보다
  새로우면 자동 재분석하도록 지문에 코드 해시를 넣어라.
- 검토 루프에서 이미지를 매번 사람이(또는 모델이) 열어보는 건 비싸다. **린터 PASS/FAIL로
  끝내고, 육안 확인은 최종 1회 문제 영역만 저해상도로.**

## 자주 겪는 실패 카탈로그

- **tight_layout이 rect를 무시**하고 경고만 내며 글자가 축 위로 겹침 → `subplots_adjust` 사용.
- **`bbox_inches="tight"`가 확보한 여백을 잘라먹음** → 여백을 쓰려면 제거.
- **원시 점을 밀도로 뭉갠 도면**은 개체 비교가 불가능 → bin 중앙값 점 + 적합선으로.
- **함대 오버레이에서 축 편향이 증폭**되어 가짜 산포처럼 보임(속도축 편향이 3제곱 관계로
  ≈17%/kn 증폭). 오버레이 축은 보정된 축을 써라.
- **개체마다 다른 기준선으로 그린 순위 도면** → 동급 평균 기준으로 전환.
- **범례에 긴 괄호 설명**을 넣어 범례가 패널을 잠식.
- 표를 도면에 넣을 때 **셀 폭 대비 텍스트 길이를 검사하지 않아** 잘림(린터의 `cell_clipped`).

**이유:** 사용자가 "2025년 회색 점이 없고 2026년에 갑자기 나빠진다" 고 지적했고, 자료는 있었다
— 결측 대수속력을 복원 대상에서 빼는 월 게이트와 NaN 슬립을 떨구는 밴드 필터가 9개월을
조용히 버리고 있었다. 복원하니 악화는 2025년 봄부터였다.

### 도면에 박는 문구·라벨·연도는 그 도면의 표본에서 다시 잰다
"not resolved (+31~58 %)" 같은 미확정 표기, 축 라벨의 연도, 창 라벨을 문자열 상수로 두면
사양이 바뀌어도 그대로 인쇄된다 — 오류 없이 그럴듯하게. **문구는 함수로, 값은 매번 계산으로.**
**이유:** 창을 3 → 6개월로 바꾸자 네 군데(미확정 폭·사다리 축·창 라벨·연도)가 낡은 채 남았고,
그중 하나는 실제 불확실도를 절반으로 줄여 말하고 있었다.

## 수확 2026-09-15 — 시계열 도면, 요청자 왕복 20여 회에서 굳은 규약

### 시간선에 세로선을 긋는 사건은 그 물리량을 바꾸는 사건만
청소 · 입거 · 도장은 긋고, 보고일 · 계약일 · 문의일은 긋지 않는다(판정 창으로만 쓴다).
**이유:** "용선주 마지막 보고일" 세로선이 성능 사건처럼 읽혀 삭제 요청을 받았다.

### 빗금은 "자료 없음" 전용 — 자료가 있는 상태에 빗금을 쓰지 마라
장기 입항을 빗금으로, 센서 결측도 빗금으로 칠했더니 구분이 안 됐다. 상태는 채움색, 결측만 빗금.
또 신뢰구간 띠와 기간 음영은 **색이 겹치지 않게** 고른다.
**이유:** 빗금 두 종류는 범례를 봐도 도면 위에서 안 갈린다.

### 도메인 의미가 있는 색은 그 범주 전용 — 기본 계열은 중립색
적재상태처럼 이미 색이 정해진 범주(청 · 주황)가 한 도면에 있으면 기본 계열에 그 색을 쓰지 않는다.
그 범주를 표시하는 **모든** 요소(산점 · 띠)가 같은 색을 따르고, 두 요소의 출처가 다르면
(센서 흘수 vs 상업 라벨) 부분 적재에서 어긋나므로 **각 요소의 출처를 적는다.**
**이유:** 산점과 띠의 색이 다르다는 지적이 표시 결함이 아니라 부분 적재라는 자료의 사실이었다.

### 글자는 데이터 위에 두지 않는다 — 축 상단에 비워 둔 띠에 둔다
y 범위를 `lo + (hi − lo)/(1 − 0.22)` 로 잡아 상단 22 %를 비우고 제목 · 기준선 라벨 · 사건 라벨을
거기 둔다. 구간 수준 라벨은 그 구간 자료의 상위 포락선 위에 둔다.
**이유:** 흰 바탕 상자로 가려도 시계열이 가려진다는 지적이 나왔다. 린터 `text_overlap`은 축 테두리
기준이라 데이터 선 · 점과 글자의 겹침은 못 잡는다 — 이건 눈으로 본다.

### 축 범위는 자료 대부분(98 % 분위)으로, 밖의 점은 가장자리 ▲ + 개수 공시
이상값 4일이 축을 0~80 %로 늘려 본체가 납작해졌다. 가장자리에 ▲로 찍고 "▲ 4 d above axis"를
각주에 적는다. 점을 지우지 않는다.

### 위아래로 쌓은 시계열 패널은 패널마다 날짜축을 단다
`sharex`로 위 패널 눈금을 숨기면 띠 패널만 잘라 볼 때 날짜가 없다. 작은 글꼴(`yy-mm`, 8.5 pt,
pad 1.5)로 패널마다 달고 세로 간격을 그만큼 늘린다.
**이유:** "시계열에 날짜 표시가 없네요" — 가장 먼저 읽히는 정보가 빠져 있었다.

### 시간축은 이야기의 원점(인도 · 청소)에서 시작하고 자료 시작을 따로 표시한다
첫 자료일에서 시작하면 인도부터 자료가 비었는지 알 수 없다.

### 산점은 신뢰구간 띠 위에 그린다
띠(α 0.2)가 산점 위에 오면 점이 흐려져 "스캐터를 잘 보이게" 요청을 받았다. zorder 로 점을 띠 위로.

## 수확 2026-09-17 — 트윈 축과 읽기 격자

### 보조축을 공유한 두 물리량 중 하나는 반드시 안 읽힌다 — 눈금이 아니라 패널을 나눠라
한 패널에 축회전수(좌)와 선속(우)을 얹었더니 선속 축이 0·5·10·15 네 눈금뿐이라 값을 짚을 수
없었다. 눈금을 늘리는 대신 **선속에 전용 패널**을 주고 범위를 자료 폭에 맞춰 좁히자 해결됐다.
두 계열의 비례 관계를 보이려고 겹치는 것은, 어느 쪽도 값으로 읽히지 않으면 이득이 아니다.
**이유:** 요청자 지적이 "선속이 잘 안 보인다"였다. 보조축은 *있다*는 것만 보여주지 *얼마다*를
보여주지 못한다.

### 격자는 2단으로 — 라벨 있는 주격자 + 라벨 없는 헤어라인 보조격자
주격자만 촘촘히 하면 눈금 라벨이 서로 붙어 읽히지 않는다(선속 1 kn 간격에서 "10 11 12"가
뭉갬). **라벨은 성기게(2 kn·10 rpm·2,500 kW), 격자선은 촘촘하게(0.5 kn·2.5 rpm·500 kW,
lw 0.35 · alpha 0.55)** 두면 값을 세어 읽을 수 있다. 시계열의 세로 격자도 같다 —
주 단위 라벨 + 일 단위 헤어라인.

### 트윈 축 패널 안의 글자는 린터가 100 % 겹침으로 잡는다 — 축 밖에 둬라
`audit_figure` 의 `text_overlap` 은 "자기 axes 안의 글자"만 면제한다. `twinx()` 로 만든
축은 **다른 axes 이므로 같은 사각형을 100 % 점유**하고, 어느 쪽 axes 에 글자를 붙이든
반대쪽과 전면 겹침으로 보고된다. 주석은 `transform=ax.get_xaxis_transform()` 으로 y>1.0,
즉 축 위에 둔다. 다만 거기엔 제목이 있으므로 제목과 주석의 폭 합을 먼저 재라.
**이유:** 린터를 끄고 싶어지는 순간이 바로 이때인데, 끄면 진짜 겹침도 같이 놓친다.

### 같은 양의 두 버전을 서로 다른 도면에 실으면 같은 이름으로 다른 숫자가 나간다
시계열 패널에 "rpm 중앙값 44"(일평균의 중앙값)를, 분포 패널에 "median 45"(시간 표본의
중앙값)를 적었다. 둘 다 옳지만 독자에게는 모순이다. **한쪽에서 뺀다** — 분포 도면이
통계를 말하고, 시계열은 추이를 말한다.
**이유:** `technical-deliverable-craft` 의 "한 가지 기준값만 제시"가 도면 사이에서도 성립한다.

## 수확 2026-11-05 — 계약 문서를 건드리는 대외 그림

### 그림의 값이 그 문서에 그 이름으로 있는가 — 없으면 그 이름으로 부르지 않는다
합계 칸만 있는 표에서 일부 몫을 "표 값"이라 라벨하면 틀린 라벨이다. 표 사이 값의 보간을 문서가 정하면 그대로 그린다(선형을 계단으로 그리지 않는다).
**이유:** 값은 내부 계산서와 일치했지만 계약 표에는 없는 칸이었고, 요청자가 계단 모양을 보고 잡았다.

### 점이 정의상 곡선 위에 찍히면 말하는 것은 데이터가 아니라 주석이다
곡선 × 입력으로 만든 점은 곡선을 벗어날 수 없다. 증거로 부르지 말고 캡션을 "Example" 로 쓴다.
**이유:** "이 플롯의 의미가 있나요" — 새 정보 없이 주석이 결론을 말하고 있었다.

### 새 비교를 그림에 넣으면 본문이 안 한 주장을 그림이 한다
숫자를 쓰지 않기로 한 메일에 표 비교 그림을 넣으면 숫자를 쓴 것과 같다. 그림 하나로 메일의 구도를 바꾸지 않는다.
**이유:** 본문을 절제한 판과 비교 그림을 넣은 판을 보고, 요청자는 절제한 판을 골랐다.
