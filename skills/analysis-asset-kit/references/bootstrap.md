# 착수 의례 — 새 프로젝트 첫 30분

목적은 설정이 아니라 **정본을 말로 못 박는 것**이다. 프로젝트가 서툰 이유는 대개 도구가
없어서가 아니라, "무엇이 정본인가"가 3주째 아무 데도 적혀 있지 않아서다.

## 1. 키트가 이 환경에서 도는지 확인

```bash
python3 ~/.claude/skills/analysis-asset-kit/assets/test_analysis_kit.py   # 15/15
```

## 2. 세 가지를 먼저 정한다 — 코드 이전에

| 결정 | 안 정하면 |
|---|---|
| **입력 정본** | 같은 수치의 출처가 둘이 되고, 나중에 어느 쪽이 맞는지 아무도 모른다 |
| **비교 기준(basis)** | 괴리가 실재인지 기준 결함인지 판정 불가 — `like-for-like-comparison` 참조 |
| **`embed_scale`** | 폰트 하한이 정해지지 않아 도면을 나중에 전부 다시 그린다 |

`embed_scale`은 산출물 형태로 결정된다. 도면이 곧 페이지면 `1.0`, 리포트 본문에 삽입되면
실제 삽입 배율의 **최솟값**(흔히 0.72~0.95).

## 3. `CLAUDE.md`를 만든다

빈칸을 남겨두지 말 것. 빈칸이 남으면 그 항목은 영원히 안 정해진다.

```markdown
# <프로젝트명>

<한 줄: 무엇을 판정하려는 작업인가>

## 정본 (SSOT)

- **입력**: <경로> — 불변, 수정 금지
- **1차 산출**: <경로> — 생성 스크립트 <경로>
- **결론·판정**: `docs/knowledge/*.md`

## 기준 (basis)

- 비교 대상: <계약/사양/시운전/타 계측>
- 정합 처리: <단위·정규화·범위·상태축 — 무엇을 맞췄는가>
- 비교 불가 항목: <있으면 명시. 없으면 "없음"이라고 적는다>

## 도면·산출물 규격

- `embed_scale = <값>` → `tiers()` 하한 <값>pt
- 임계: <값> / 출처: <산정 모집단>
- 자산: `analysis-asset-kit` (스타일·린터·판정) — 자작 금지

## 빌드

```bash
<명령>
```

## 세션 종료 시 (수확)

아래 3문을 판정하고 승격한다. 상세는 `analysis-asset-kit/references/harvest.md`.

- [ ] 이 판정이 **다른 대상에서도** 참인가 → 스킬 승격
- [ ] 이 코드가 **프로젝트 배선 없이** 도는가 → 키트 승격
- [ ] 둘 다 아니면 → `docs/knowledge/`에 근거와 함께 존속
```

마지막 절이 핵심이다. 수확 의례가 사람의 기억이나 세션의 규율에 의존하면 반드시 유실된다.
**파일이 시키게 만든다.**

## 4. 출력 트리

```
input_files/     불변 입력 (gitignore)
docs/knowledge/  판정·결론 — 프로젝트 정본
output/          재생성 가능 산출물 (gitignore)
scripts/         분석 스크립트, 접두어로 그룹화
```

## 5. 첫 도면을 그리기 전에

- `tiers(embed_scale)` → `configure()` → `style_axis()` 경로로만 폰트·색을 잡는다
- 자작 팔레트·자작 곡선 금지. 적합은 검증된 fitter 재사용
- 첫 도면부터 `audit_figure(fig, min_font_pt=t.floor)`를 붙인다. 나중에 붙이면 안 붙는다
