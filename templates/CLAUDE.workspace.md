분석 · 검증 작업의 최상위 작업공간. **[LEDGER.md](LEDGER.md)가 유일한 창구다.**

## 1. 창구 — 대장을 거치지 않는 일은 없다
새 작업은 `LEDGER.md` 에 행이 생긴 뒤 시작한다. 착수는 `case-intake` 스킬이 골격 생성과 대장 등재를 한 번에 한다.
수작업으로 디렉토리를 만들면 두 달 뒤 그게 무엇이었는지 아무도 모른다(임시 폴더에 납품 건이 섞이고 한 건이 여러 곳에 흩어진 사례).

## 2. 배분 — 결과물이 누구에게 가는가로 나눈다
| 분류 | 판별 | 규율 |
|---|---|---|
| **platform** | 여러 건이 계속 소비하는 자산 | 건별 작업이 쓰지 않는다. 읽기 전용 소비 |
| **case** | 한 대상 · 한 질문에 대한 판정. 납품 있음 | 아래 골격 강제. 결론은 `docs/knowledge/` |
| **inquiry** | 외부 질의 회신 | 회신 규약을 따른다 |
| **scratch** | 버릴 것 | 30일 후 승격 또는 삭제 |

건은 `cases/` 로 모은다. 옮길 때: ① 그 경로를 쓰는 프로세스 · 서비스 · 예약 작업이 없는지 ② 참조를 센다 ③ 돌고 있는 코드가 옛 경로를 쓰면
코드를 고치지 않고 옛 자리에 호환 링크 ④ 건 안의 자기 참조는 새 경로로 ⑤ 대장 · 작업 이력 페이지의 경로를 같은 날 고친다.

## 3. 골격
```
YYMMDD_<대상>_<요지>/
├── README.md          ← 한 줄 결론 · 정본 선언 · 파일 안내. 첫 커밋에 존재해야 한다
├── scripts/           ← 생산 코드
├── input_files/       ← 불변. 수정 금지, 파생물만 만든다
├── evidence/          ← 판정 근거
├── results/           ← 중간 산출
├── exports/           ← 납품물
├── figures/
└── docs/knowledge/    ← 평결. gitignore 대상 폴더에 두지 않는다
```
`README.md` 의 한 줄 결론을 빈칸으로 두지 말 것. 빈칸은 영원히 안 채워진다.

## 4. 착수 3결정 — 코드보다 먼저
| 결정 | 안 정하면 |
|---|---|
| 입력 정본 | 같은 수치의 출처가 둘이 되고 어느 쪽이 맞는지 모르게 된다 |
| 비교 기준(basis) | 괴리가 실재인지 기준 결함인지 판정 불가 |
| 도면 크기 기준(`embed_scale`) | 폰트 하한이 안 정해져 도면을 전부 다시 그린다 |

## 5. 유산 — 승격 3단
```
건 docs/knowledge/      ← 기본값. 이 대상의 수치 · 이름 · 결론
   ↓ 다른 대상에서도 참인 사실
도메인 지식 폴더        ← 도메인 위키
   ↓ 대상 고유명이 빠져도 성립하는 판단
~/.claude/skills/       ← 규범 + 실행 자산
```
승격 O: 「임계는 산정 모집단과 함께 다녀야 한다」 / 승격 X: 「warn=(5,15)」. **이유를 반드시 함께 적는다.**

## 6. 발화 장치 — 기억에 의존하지 않는다
| 시점 | 장치 | 하는 일 |
|---|---|---|
| 세션 시작 | `.ops/ledger_context.sh` | 진행 중 · 미확인 건 + 미결 + 수확 대기 큐를 컨텍스트에 주입 |
| 세션 종료 | `.ops/harvest_enqueue.sh` | 실작업 파일을 고쳤으면 `.ops/harvest_queue.jsonl` 에 적재 |
큐는 다루기 전까지 사라지지 않는다. 수확을 마치면 큐 파일을 비운다.

## 7. 공용 자산을 건드리지 않는다
다른 세션 · 협업자의 산출물은 읽기와 복사만. 수정 대신 그 함수가 이미 내보내는 열을 소비한다.
커밋은 경로를 명시해 스코프를 한정한다 — 전체 추가는 남의 미커밋 작업을 함께 담는다.

## 8. 작업 중량
탐색적 분석 · 일회성 산출물은 인라인으로 직접 쓰고 결과 보며 반복한다. 중량 프로세스(정식 계획 · 다단계 리뷰 · 하위 에이전트)는
(a) 여러 독립 파일 병렬 수정 (b) 회귀 위험 큰 생산 코드 (c) 명시적 요청 — 셋 중 하나일 때만.
