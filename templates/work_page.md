# 작업 이력 페이지 양식 (`wiki/works/<slug>.md`)

**목적**: 이 건을 처음 보는 사람(또는 새 세션)이 10분 안에 ① 지금 어디까지 왔고 ② 왜 이렇게 됐고 ③ 무엇이 남았고
④ 어디를 열면 되는지 알게 한다. **결과물 요약이 아니라 경과와 결정의 이유가 핵심이다** — 결과는 건 폴더에 이미 있다.

## 규칙
- 근거 없는 문장 금지. 흐름·결정의 각 줄 끝에 근거 포인터 1개 이상: `work:<경로>` · `work:<경로>@<sha7>` ·
  `work:portfolio#MM-DD HH:MM` · `session:<uuid>` · `mail:<f>/<m>` · `note:…`. 경로에 공백이 있으면 상위 폴더를 가리킨다.
- 추론은 `(추정)` 표시. 사용자 결정은 「사용자」로 명시(근거: 메모리 파일이면 `work:` 대신 본문에 메모리 파일명을 적는다).
- 수치는 옮기지 않는다 — 꼭 필요하면 「값(판본·파일)」으로 출처와 함께. 메일 원문 인용·개인정보 금지.
- 바뀐 결정은 지우지 않고 「→ 이후 ○○로 변경(날짜, 근거)」로 둘 다 남긴다 (`SUPERSEDES` 정책).
- 길이: 본문 150~350줄 이내. 커밋을 나열하지 말고 **국면(phase)** 으로 묶는다.
- 문체: 「~다」 평서. 현업 용어 그대로(UWC, Hull Fouling, Noon Report 등).

## 틀
```markdown
---
name: <slug>                      # 파일명과 같게. 소문자-하이픈
type: work
title: <사람이 부르는 이름> — <한 구절 요지>
description: <한 줄 현재 상태. 「~단계, 다음은 ~」>
updated: YYYY-MM-DD
work_path:
  - <claude_work 기준 경로>       # 신선도 판정 대상 (여러 개 가능)
status: <LEDGER 상태 — 진행중/운영중/판정완료/납품완료/중단/미확인>
sources:
  - work:<경로>
  - work:portfolio#MM-DD HH:MM
  - session:<uuid>
relations:
  - RELATES-TO-CASE :: [[다른 work 또는 case slug]]
  - INVOLVES :: [[vessel/org/person slug]]
---
```
