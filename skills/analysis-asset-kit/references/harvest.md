# 수확 의례 — 세션 종료 시 승격 판정

이 의례가 돌지 않으면 키트는 굳어 죽고, 다음 프로젝트에서 다시 자작이 시작된다.
**키트의 존속 조건이다.**

## 판정 3문

세션에서 새로 알아낸 것 하나하나에 대해:

| 질문 | 참이면 | 귀속 |
|---|---|---|
| 이 판정이 **다른 대상에서도** 참인가 | 대상 고유명·수치가 빠져도 문장이 성립 | 스킬 승격 |
| 이 코드가 **프로젝트 배선 없이** 도는가 | 경로·대상명·조직 매핑 import가 0 | 키트 승격 |
| 둘 다 아님 | — | 프로젝트 `docs/knowledge/` 존속 |

세 번째가 기본값이다. 대부분의 발견은 프로젝트에 남는 게 맞다. **승격을 남발하면 키트가
특정 프로젝트의 사투리가 된다.**

## 스킬 승격

승격 대상은 *판단*이지 결론이 아니다.

- 승격 O: "기준선이 개체마다 다르면 그 축으로 서열을 그리지 마라"
- 승격 X: "AL_GALAYEL은 계약 미달 −11.09%"
- 승격 O: "임계는 산정 모집단과 함께 다녀야 한다"
- 승격 X: "warn=(5,15)"

어느 스킬로 갈지: 대조 설계 → `like-for-like-comparison` · 도면 → `analysis-plot-craft` ·
산출물 → `technical-deliverable-craft` · 운영·정본 관리 → `analysis-project-operations` ·
도메인 각론 → 해당 도메인 스킬.

**이유를 반드시 함께 적는다.** 이유 없는 규칙은 다음 사람이 잘못된 상황에 적용한다.

## 키트 승격

1. 프로젝트 배선을 제거하고 순수 함수로 만든다 (입력 = 표준 자료구조, 출력 = 값·판정)
2. 임계·경계는 **기본값 없는 인자**로 뺀다 (SKILL.md 계약 4)
3. 답할 수 없는 상태는 `Outcome.rejected(Reason.…)`로 반환한다 (계약 3)
4. `assets/test_analysis_kit.py`에 **실수 하나를 못 박는 테스트**를 추가한다 —
   커버리지가 아니라 재발 방지가 목적
5. 전체 테스트를 돌리고 통과를 확인한다

### 깨는 변경 금지

키트는 진행 중인 여러 프로젝트가 동시에 소비한다. **추가만 한다.**

- 함수 시그니처 변경 → 새 함수를 추가하고 기존 것은 남긴다
- 색·하한 값 변경 → 기존 산출물이 조용히 달라진다. 상수 추가로 처리한다
- 임계 기본값 도입 → 금지. 계약 4 위반

불가피하게 깨야 하면, 그건 세션 말미 승격이 아니라 **별도의 개정 작업**이다.

## 승격하지 않는 것

- 특정 대상의 수치·이름·결론
- 한 번만 유효했던 우회(workaround)
- 확신이 없는 규칙 — 두 번째 프로젝트에서 다시 만나면 그때 올린다

## 잔여 기록

승격하지 않기로 한 것도 프로젝트 `docs/knowledge/`에 남긴다. **판정한 흔적이 없으면 다음
세션이 같은 판정을 처음부터 다시 한다** — 이 의례가 막으려는 것이 바로 그것이다.

## 대장 갱신 — 승격 판정과 같은 세션에서

`~/claude_work`에서 작업했다면 승격 판정만으로 끝나지 않는다. **지식이 어디 있는지가
대장에 없으면 승격해도 못 찾는다.**

1. `~/claude_work/LEDGER.md`에서 이번에 다룬 건의 행을 찾는다.
2. **상태**를 갱신한다 — `진행중` → `판정완료`/`납품완료`/`중단`.
   - `미확인`이었다면 이제 채운다. 그게 이 세션에 진 빚이다.
   - `중단`으로 내릴 때는 **재개 조건**을 함께 적는다.
3. **정본 열**이 실제 결론 문서를 가리키는지 확인한다.
4. 이 건을 넘어 남은 것이 있으면 `## 미결` 절로 올린다 —
   **무엇이 있어야 결판나는지**를 함께 적는다. "야드 회신 필요", "반례 수집 필요" 형태.
5. 건 `README.md`의 **한 줄 결론**과 대장 상태를 **같은 커밋에서** 고친다. 따로 하면 어긋난다.

6. 작업 이력 페이지(`second_brain/wiki/works/<slug>.md`)는 **건 세션이 쓰지 않는다** — 총괄(second_brain) 소유다.
   건 세션은 커밋·문서만 남기면 된다. 그 변화가 LINT 의 낡음 판정과 이 큐를 통해 다음 second_brain 세션에 갱신 대기로 뜬다.

## 큐 비우기

수확을 마쳤으면 마지막에:

```bash

```

큐는 비우기 전까지 매 세션 시작에 다시 뜬다. **그게 이 장치의 요점이다** — 이 의례는
2026-07-29부터 문서로 존재했으나 아무것도 부르지 않아 한 번도 돌지 않았다.

이번 세션에서 수확을 하지 **않기로** 했다면 큐를 그대로 둔다. 비우는 것은 처리했다는 뜻이지
넘어갔다는 뜻이 아니다.
