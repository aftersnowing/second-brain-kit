## 자체 스킬 우선

아래는 실제 프로젝트에서 축적한 자체 스킬이다. **해당 상황이면 플러그인 범용 스킬보다 먼저 로드**한다. 표의 왼쪽이 트리거다.

| 이런 작업이면 | 이 스킬 |
|---|---|
| **새 건을 착수하거나 새 디렉토리를 만들려 할 때 — 무엇보다 먼저** | `case-intake` |
| **새 프로젝트 · 새 대상에서 분석을 시작하거나, 도면 · 판정 · 검증 코드를 작성** | `analysis-asset-kit` |
| 측정값을 계약 · 사양 · 보고서 · 다른 측정과 대조해 「얼마나 차이 나는가」를 판정 | `like-for-like-comparison` |
| 도면 · 차트 · figure 제작 (matplotlib 포함) | `analysis-plot-craft` |
| 리포트 · 워크북 · 덱 등 납품 산출물 제작 | `technical-deliverable-craft` |
| 산출물이 여러 개로 갈라지거나 세션 · 기간이 길어질 때 | `analysis-project-operations` |
| **산출물 초안을 요청자 피드백으로 다듬는 왕복이 시작되거나, 피드백을 받았을 때** | `deliverable-feedback-loop` |
| <업종 고유 반복 업무의 트리거 문구> | `<업종 스킬>` |

- **애매하면 로드해서 훑고, 안 맞으면 버린다.** 안 읽어서 같은 실수를 반복하는 쪽이 비싸다. 단 안 맞는 스킬의 규칙을 억지로 끼워 맞추지는 말 것.
- `analysis-asset-kit` 은 **자산 배달 스킬**이라 다른 것과 배타적이지 않다. 나머지가 판단 규범을 주고, 이쪽이 그 규범의 구현체(스타일 상수 · 도면 린터 · 판정 · 거부 사유)를 준다. 도면이나 판정 코드를 쓰기 전에 **먼저 로드해 import 경로를 잡는다** — 자작하면 매번 결과가 달라진다.
- 여러 개가 걸리면 **대조 → 분석 → 도면 → 산출물 → 운영** 순으로 본다. `like-for-like-comparison` 은 도메인 무관이라 단독으로도 걸린다.
- 스킬 본문(SKILL.md)만 먼저 읽고, `references/` 는 그 국면에 도달했을 때 개별로 읽는다.
- `case-intake` 는 **순서상 항상 첫 번째**다. 어느 건에 속하는지 정해지기 전에는 나머지가 어디에 산출물을 둘지 알 수 없다. 5분짜리 질문이면 이것도 건너뛴다.

## 작업 대장

`<작업 폴더>` 의 작업은 **LEDGER.md 가 유일한 창구**다. 운영 규율은 `<작업 폴더>/CLAUDE.md`.
세션 시작 시 진행 중 건 · 미결 · 수확 대기 큐가 자동 주입되고(`SessionStart` 훅), 세션 종료 시 수확 대기가 적재된다(`SessionEnd` 훅).
큐를 비우는 절차는 `analysis-asset-kit/references/harvest.md` 맨 아래.
