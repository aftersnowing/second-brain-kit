# 기술 산출물 제작 규범

15척 함대 계약검증 산출물(척당 45p PDF + 14시트 워크북 + 함대 요약 4종)을 두 달간 만들며
사용자 지적으로 배운 것들. **독자는 데이터 분석가가 아니라 계약 상대방과 임원**이라는 전제가
모든 규칙의 뿌리다.

## 요지

산출물은 분석의 기록이 아니라 **협상·의사결정 도구**다. 그래서 세 가지가 동시에 성립해야 한다:
읽는 사람의 언어로 쓰여 있을 것, 숫자가 어디서 왔는지 추적 가능할 것, 형식 결함이 없을 것.
셋 중 하나만 깨져도 내용의 신뢰가 함께 깎인다.

## 문체·톤

- **무채색·심플한 디자인 + 높은 내용 밀도.** 컬러 강조를 빼고 그레이스케일 + 단일 액센트로
  가되, 표와 수치는 촘촘하게. "디자인을 줄이고 내용을 늘린다"가 임원 문서의 기본값이다.
- **명사형(체언) 종결**을 쓴다 — "~환산 / ~비교 / ~상회 / ~도출". 흐름 화살표(→)는 허용.
  종결 스타일이 문서 전체 톤을 좌우하므로 애매하면 착수 전에 1회 확인하라.
- **용어를 격식화**한다: 되돌림→재투영/환산, 더함→가산, 천장→상한, 우리→실측/선주,
  magic number→임의 상수, "왜 X인가"→"X 근거".
- **수치는 정본에서 같은 수식으로 재계산**해 넣는다. 임의 상수·수기 전사 금지. 출처를 footer에
  명기한다. (첫 산출물이 "임원 보고용은 아닌 것 같다"는 평을 받은 원인은 내용이 아니라
  구어체 용어와 명사 나열 fragment였다.)

## 용어 통제 — 두 방향

**① 도메인 언어를 쓴다.** 데이터사이언스 용어로 기울지 말고 그 분야(해운·조선·플랜트 등)의
표현을 주로 쓰되, 통계 용어는 보조로만. 물리 현상을 서술하는 표현이 상대방의 계약 조항·
공급자 자료와 직접 대응되기 때문에 방어력이 높다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 잔차 RMS가 크다 | 실측이 공급자 곡선 대비 몇 g/kWh 벗어난다 |
| 이상치 제거 | 계측 결함 구간 배제 |
| poly2 misspecification | 2차 곡선이 중부하 평탄부를 표현하지 못함 |
| 검출 / 유의 / 판별 불가 | 유의 저하 / 경계 / 차이 없음 |
| 잡음 바닥 · placebo 최대치 | 판정 한계(같은 길이 사전 구간의 자연 변동 최대치) |
| 정온일 필터 | 양호 기상일(파고 · 풍속 조건 명시) |
| 부트스트랩 CI | 95 % 신뢰구간(항해일 기준) |

**② 구현 내부 어휘를 제거한다.** 클라이언트가 보는 텍스트에서 gate·artifact·fallback·
pipeline·파일 경로·내부 토큰(`bf_gate_max_le_5`, `.csv`, `MANIFEST` 류)을 도메인 표현으로
치환하라: gate→"weather limit"/"consistency check", fallback→"reference value",
pipeline→"procedure", 경로→산출물 설명. QA 체크명·계보 표·상태 열은 **표시 시점에 도메인
라벨로 매핑**한다.

- **기계검증**: 렌더된 텍스트를 `gate|fallback|artifact|pipeline|\.csv|\.json|manifest|_`로
  grep하는 테스트를 둔다. 우리는 이 스캔이 최종 직전에 실누수 2건을 잡았다(36파일 스캔).

## 도면 설계

**→ 전용 스킬 `analysis-plot-craft` 참조.** 비교 기준·축 선택, 텍스트 최소화, 색 규약,
임베드 폰트 하한, 도면 QA 린터, 프리뷰 루프가 그쪽에 있다.

산출물 제작 맥락에서 놓치기 쉬운 두 가지만 여기 남긴다:

- **도면은 리포트에 0.72~0.95배로 축소 삽입된다.** 네이티브 9pt가 인쇄본 6.5pt가 되므로
  폰트 하한을 임베드 배율로 나눠 잡고 빌드 게이트로 검사하라.
- **본문 텍스트와 도면이 같은 수치를 두 번 말하지 않게 한다.** 패널 안 칩에 있는 값을
  캡션·본문에서 되풀이하면 나중에 한쪽만 갱신되어 문서 내 불일치가 된다.

## 단계 스토리라인

원자료에서 결론까지 한 줄로 읽히도록 구성한다. 각 단계마다 **설명 문서 + 그 단계를 보여주는
도면**이 짝을 이루고, 산출 단위는 **개체별 + 전체 요약 두 가지**를 함께 설계한다.

```
로우데이터 → 필터링(단계별 잔존) → 열량/단위 정규화 → 물리 보정 → 최종 산점 → 곡선 적합 오버레이
```

새 도면·문서를 만들 때는 ① 이 중 어느 단계인지 명시 ② 용어를 도메인 쪽으로 선택
③ 개체/전체 두 단위 설계 ④ 기존 중복 도면을 이 스토리라인에 흡수. 트랙이 여러 개면
**트랙마다 단계 구성이 다르다는 점**에 주의(직접 실측 트랙에는 정규화·보정 단계가 없다).

## 표·워크북 공학

- **열 폭을 라벨 길이에 맞춰 미리 설정**한다. 값이 오른쪽 셀에 있으면 라벨이 overflow로 보이므로
  폭을 늘리거나 라벨을 줄인다. "클리핑 없음"은 폭 vs 라벨길이로 프로그램 체크 가능하다.
- 헤더는 wrap + center + 행높이 고정, 비교표는 thin border 박스, **분석값은 음영 / 참조값은
  무음영**으로 규약을 세우고 전 시트에 일관 적용한다.
- **중복 배제**: 같은 정보가 다른 시트에 있으면 재수록 금지.
- **의사결정용 Summary 는 표 한 장이다.** 행 = 시간순 기간(기준 → 사건 → 사건 후 구간들), 열 =
  판정에 필요한 지표만(값 · 신뢰구간 · 판정 · 운영 환산값 · 맥락 일수 · 비고). 결론 1줄 + 기준 1줄을
  표 위에. 민감도 · 대조 · 진단은 다른 시트나 도면으로 보낸다.
  **이유:** 민감도 · Noon Report 대조 · 분석 조건을 Summary 에 함께 담은 첫 워크북이 "이렇게 복잡하면
  안 된다"로 반려됐다. 독자는 한 장으로 결정하고 근거는 필요할 때 찾는다.
- **한 가지 기준값만 제시**한다. 후보 여러 개를 병기하면 독자가 어느 것이 결론인지 모른다.
  진단용 참조값을 굳이 남기려면 "기준 아님"을 라벨에 박아라.
- **원본 시트는 verbatim으로 보존**하고 개정본을 쌍둥이 시트로 추가한다. 원본이 Diff의 분모다.
- **수식을 살려서 쓰면 검증이 쉬워진다**(Total 열 = M/E + G/E 라이브 수식). 다만 공급자 파일의
  상수가 리터럴·셀참조·시트체인으로 제각각 박혀 있을 수 있으므로, 고정 셀 주소를 덮어쓰는
  방식은 **조용히 실패**한다(11척 중 3척만 반영된 사례). 수식을 파싱해 가산항을 분리하고
  **전수 셀 검증 게이트**를 둘 것.
- **외부 참조는 pin**한다. 다른 워크북을 가리키는 참조가 남으면 수령자 환경에서 깨진다.
- 기계 데이터는 워크북이 아니라 별도 `data/*.csv`로. 워크북은 사람이 읽는 문법
  (Cover & Summary / 본표 / 대조 / Basis & Notes)을 유지한다.
- **지적받기 전에 서식을 완결**하라. 폭·잘림·중복·기준값 같은 기계적 디테일을 매번 지시받는 건
  낭비다.

## 조판(LaTeX) 실패 모드

- **큰 그림(float)과 분할 불가능한 표는 같은 페이지에서 충돌한다.** 그림이 상단을 점유하면
  남은 공간에 표를 넣을 합법적 분리점이 없어 라벨 고아 또는 영역 이탈이 강제된다.
  → **표를 분할 가능한 형태(longtable)로 만들면 클래스 자체가 사라진다.**
  공간 확보(needspace)·라벨 결합 같은 증상 대응은 새 페이지 구성에서 다시 터진다.
- float 배치에서 **`!` 플래그는 영역 검사(type area)를 무력화**한다. 큰 그림 2장이 한 페이지에
  쌓여 144pt 초과한 사례가 있다. 배치 지정에서 `!`를 쓰지 말 것.
- **하단(b) 배치 금지**: 분할 불가 표가 하단 float를 덮어쓴다.
- 커버·헤더의 한 줄 필드는 길어지면 페이지 밖으로 잘린다. 문자열을 짧게 유지하고 `p{}` 컬럼으로
  줄바꿈 여지를 둔다.
- 절 경계마다 `\clearpage`를 넣지 말고 `\FloatBarrier` + `placeins[section]`으로 묶으면
  빈 여백이 크게 준다(15척 전부 50p→45p).

## 검증 — 눈이 아니라 스크립트로

| 게이트 | 무엇을 잡나 |
|---|---|
| 조판 로그의 Overfull hbox/vbox 임계 | 표·그림의 영역 이탈 (결함 빌드 15/15 차단 실적) |
| 금칙어 스캔 | 내부 구현 어휘 누수 (36파일) |
| 항등식 전수 셀 검사 | 구성요소와 총계 불일치 (4,260 수식 셀) |
| 정본 대조 | 산출물 간 수치 불일치 (944셀) |
| PDF 무결성(pdfinfo) + 페이지 수 균일성 | 빌드 로그가 OK인데 깨진 파일 |

**빌드 성공 로그는 파일이 온전하다는 뜻이 아니다.** `[OK]`가 찍힌 채로 trailer가 깨진 PDF가
납품 직전까지 갔던 적이 있다.

**★단, 이 게이트들이 원리적으로 못 보는 클래스가 하나 있다 — 기준(basis) 정합.**
"두 숫자가 **같은 것을 재고 있는가**"는 의미의 문제라, 양쪽이 모두 타당하고 단위가 같으면
위 검사를 전부 통과한다. 실제로 테스트 156건·검증기 전수 PASS·린터 clean·해시 무결 상태에서
대조값이 10% 틀려 있었고, 발견 경로는 **렌더된 숫자를 읽은 것**뿐이었다.

- 그래서 **숫자 검수는 "스크립트가 못 잡는 나머지"가 아니라 별도 게이트**다. 대상은 서식이
  아니라 표의 대조값이고, 묻는 것은 "이 크기가 말이 되는가"다.
- **한계·주석을 문장으로 적기 전에 그 숫자를 렌더해서 보라.** 작은 한계를 공시하려다 13배 큰
  결함을 찾은 적이 있다.
- 절차는 `like-for-like-comparison`(R7·괴리 진단 사다리).

## 반복 비용 최소화

- **파일럿 우선**: 서식·레이아웃 변경은 개체 1건만 빌드 → 게이트 → 통과 후 전체.
  파일럿 없이 돌린 전체 빌드 1회가 통째로 폐기된 적이 있다.
- **렌더 확인은 최소로**: 페이지 이미지를 검토 루프마다 열지 말고, 게이트 PASS/FAIL로 끝낸 뒤
  최종 1회만 문제 영역을 저해상도로 크롭해 본다.
- **컨텍스트 캐시 + 재렌더 전용 경로**를 만들면 조판 반복이 몇 배 빨라진다(전체 재빌드
  11분 → 133초). 단 **숫자가 바뀌는 변경은 캐시가 못 본다**는 한계를 명시하고 오류로 막아라.
- **요청 배칭**: 서식 지적을 모아서 한 사이클에 처리하도록 유도한다.

## 수확 2026-10-28 — 상대가 결정하는 성능 보고 (Word 1쪽 + 대시보드 워크북)

용선주가 청소 · 검사를 결정할 자료를 사내 담당을 거쳐 낸 건, 18판에서 굳은 형식.

- **보고서 1쪽 골격**: 결과 2줄 → 전후 표 1개(8행 안: 항해일 · 값[신뢰구간] · 판정[한계] · 기준 위 일수 · 양호 기상 · 상대 필터 ·
  속력 저하 · 보조 지표) → 보조 수치 한 줄 → 제외 구간 한 줄 → 결론 → 방법 표. 그림은 뒤 쪽. 표 3개 판은 "복잡"으로 반려됐다.
- **워크북 = 대시보드 + 근거 탭**. Summary 의 값은 근거 탭을 가리키는 수식(MEDIAN · COUNT · COUNTIF · SUMIF · 환산식)이고 Excel 로
  재계산해 캐시를 채운다. 관문 = 수식 값 ↔ 분석값 · 오류 0 · 잘림 0. 상세 탭은 표 위 + 근거 행 아래(같은 시트).
  **"AI slop" 신호**: 시트 10개 · 긴 열 이름 · 값 붙여넣기 · 산문 셀 — 첫 판이 이 평을 받았다.
- **상대가 이미 받은 형식**(이전 보고의 표)은 논리를 해치지 않는 선에서 탭 하나로 유지한다. 상대가 그 형식으로 읽는다.
- **기간 · 조건 정의는 상대가 쓴 말로** + 자료 확인 한 줄. 사내에서 따로 쓰던 제3의 정의는 본문에 쓰지 않는다.
- **상대 요청 항목마다 위치(시트 · 쪽)를 메일에 지도처럼** 적는다. 숫자를 메일에 다시 늘어놓지 않는다.
- 단위: 비분석가 독자에게 %p 금지 — "같은 속력 평상시 동력 대비 %"처럼 무엇 대비인지가 단위에 들어간 %로.
- 중계자(사내 담당)가 상대에게 쓰는 구조면 **중계자에게 보내는 메일 + 상대용 첨부(영문)** 까지만. 상대에게 보낼 메일 초안은 중계자 몫이다.

- **정확도는 채택한 방법 것만.** 「오차 5.6 % (단순 연장 7.8 %)」에서 괄호를 지웠다. 대안 비교는 근거 파일 몫이다.
- **같은 여유는 한 표현으로.** 「경계 대비 ▼3.2 %」가 있으면 「잔여기간 허용 악화 ▲19.4 %」는 같은 사실의 두 번째 표현이라 지웠다.
- **자료가 덜 모인 전망은 그 상태부터.** 머리 문장을 「보정 기록 누락분 요청 중 · 반영 후 업데이트」로 바꿨다. 읽는 사람이 숫자를 잠정치로 읽게 한다.

## 수확 2026-11-05 — 계약 상대에게 보내는 입장 서면

계약표 검증 방법론을 두고 상대와 주고받은 회신을 13판 돌리며 굳은 판단.

### 문장마다 「상대가 다음 쟁점에서 이 문장을 어디에 쓰나」를 잰다
표로 돌린다: 문장 · 상대가 쓸 방식(예상) · 번지는 쟁점 · 값 · 수정.
**이유:** 값이 작은 항목의 회신에 "실제 소모 수준을 반영하지 못한다"고 쓰려 했는데, 그 문장은 훨씬 큰 항목에서 "표는 실측이어야 한다는 것이 당신들 입장"으로 돌아올 수 있었다. 큰 쟁점을 언급하지 않아도 문장은 번진다.

### 작은 양보는 세 겹으로 — 범위 · 이유 · 최종 입장 유보
무엇을 어디까지 받는지 좁히고, 이유를 일반 원칙이 아니라 그 항목의 사실로 적고, 전체를 본 뒤 최종 입장을 내겠다고 남긴다. 수용 · 철회를 선언하지 않는다.
**이유:** 세 겹이 없으면 양보가 선례가 되고, 세 겹이 있으면 양보해도 다음 협의 자리가 남는다.

### 이번 논리를 다음 쟁점에 대입해 본다 — 불리하면 문서 구조까지 올린다
**이유:** "측정이 없으니 보정이 아니다"만 쓰면 "그럼 측정값이 곧 정답"으로 돌아온다. 두 쟁점을 함께 세우려면 문서 구조 수준의 한 문장(표 = 모델 값, 측정 = 보정 입력)이 필요했다.

### 문장 세기는 증거 강도까지만 — 받칠 표를 지금 못 내면 그 문장도 못 쓴다
"틀렸다" 대신 "이 방식으로는 확인되지 않는다". 요청자의 말도 증거 선까지 낮춰 제안한다. 보고값이 고정 기입인지 먼저 본다.
**이유:** 강한 문장은 "자료를 달라"를 부르고, 자료를 내면 약점이 함께 나간다.

### 상대가 "문서의 취지"를 말하면 단어 수와 단계 구조로 대조하고, 같은 단어의 대상을 가른다
**이유:** 상대의 핵심어가 문서에 0건이었고, 같은 동사를 양쪽이 다른 대상에 쓰고 있었다. 오해로 몰지 않고 정의 차이로 다루면 문장이 더 정확하고 부드러워진다.

### 공감 문장도 인용된다 — 답하는 메일에 없는 말을 가져오지 않는다
**이유:** 상대의 제약을 받아 준 첫 문장이 "그 제약이 기준"이라는 인정으로 읽힐 수 있었고, 답하는 메일에는 있지도 않은 말이었다.

### 레드팀 예상을 사실로 옮기지 않는다 — 실제 구조는 상대의 서면 약속 체인에서
**이유:** 상대 입장에서 가정한 "우리 동의 없이도 진행 가능"을 사실처럼 보고했다가 요청자가 잡았다. 상대 메일을 모으니 "시행 전 검토"를 스스로 약속해 둔 상태였다.
